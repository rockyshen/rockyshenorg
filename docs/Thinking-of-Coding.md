1、算法是内功。
算法提供最底层的思维方式如何高效的实现代码，例如二叉树的遍历，就提供了面多二元分裂的树结构时的遍历框架型思维方式。如果不这样想，很容易漏！

2、抽象能力在编程中很重要，拒绝重复！
只要有重复，就一定要抽象出来。重复的小功能，抽象成自定义函数；重复的属性，抽象成类；重复的完整功能，抽象成装饰器。

我热爱Coding这一行，首先整个行业都很年轻，计算机的发展不过几十年，没有太重的包袱。另外所有的技术都很直接面向技术，我讨厌那种把一个概念复杂化的专业和人（我发现编程Up主中也有这种人，往往不把事情说透，藏着掖着，还会把简单的概念复杂化。这种人要避而远之）。另外有一些Up主充分贯彻了Coding精神，面向解决实际问题，将问题简单化讲解/

另外，我发现Coder有一种整体精神，乐于分享，乐于助人（社区文化，开源文化），简直太酷啦！不像有的行业，筑起高高的壁垒，看似保护了自己，其实也限制了自己。（众人拾柴火焰高）。即便是最牛的顶级大师，也会公开email，有问题都可以直接email问他们。

阅读 CODE_OF_ CONDUCT和 CONTRIBUTING 文件。它们定义了为参与者的相关行为设定基本规则，一些 variable 的命名规则等。之后写的code 也都要符合这个文件里的规则。

在githubpage 的issue 目录里看看目前这个应用还有哪些 bug 或者新的feature 需要完善，可以多看看评论，不要着急直接上手写 code。新手的话建议就是写一个新的feature，找到自己合适的 issue 后，我们就可以开始着手写 code，并在完成后 create pull request，能不改 bug 就不改，更不要尝试refactor屎山代码。

3、程序员最厌恶的是重复，reuse，一旦有复用的代码，必须想方设法给删掉。lambda表达式！

框架的迭代，是行业充满活力的象征，是程序员为社区共享正向循环。越是利用业余时间贡献代码，PR完善框架，自己的技能、reputation约提升，越能在工作中获得promotion！
不像有的行业在不断的故步自封！！！！

学习方法的时间
1、学习最重要的是建立连接，而不是记住单个知识点。
2、做笔记千万不要照抄，要手动写。记笔记的难度和掌握成反比！

转码路上的难关：学习太过，生活失衡，伴侣反感！

coding能让我进入心流状态，但是也会生活失衡！

编程教给我的事情：任何一个复杂的项目（系统），不要胆怯，拆分成一个个小模块去完成！
Coding锻炼了我的一种思维方式，把大问题拆分成小问题，逐个去解决（递归思想，分治思想）

在Coding的领域，不存在哪一天，所有和Coding相关的知识我都学完的那天，是不存在的！正如尚硅谷的那句“名言”：让天下没有学得完的技术。虽然是句玩笑话，但是确实体现了Coding领域的特点，充满了新知识，活跃的技术层层叠叠！
推友说：我干技术十多年，还没遇到过新项目不需要学习新知识就能搞定的！
这是一个开发老兵的经验，我也知道了，所以前面开发几个项目，都有遇到问题真的是常态啦！遇到问题，解决问题！nice！

开源项目完美体现了人类群星闪耀，有志之士在GitHub集合，为一个项目贡献代码，使这个项目往稳定完善的方向发展！  
参与一个开源项目，有点像玩养成游戏，大家一起培养一个项目。太酷了
